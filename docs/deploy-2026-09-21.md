# Primeira instalação — 21/09/2026

O responsável afirmou nesta tarefa que revisou o projeto e autorizou correções e publicação. Aprovação registrada na conversa; não há alegação de revisão independente ou aprovação na API do GitHub.

## Escopo desta revisão

- Correção do contraste dos placeholders e do foco por teclado, com regressão automatizada.
- Provisionadores de **primeira instalação**, que recusam diretórios, contas, bancos e serviços preexistentes. Não usar como atualizador genérico.
- Ambientes separados, PostgreSQL com proprietário e runtime distintos, Redis autenticado próprio e ClamAV restrito ao loopback. Pacotes ClamAV são extraídos dentro do projeto sem instalação global nem execução de scripts de pacotes.
- Código em release identificada por SHA, dependências travadas e processos sem root.
- Virtual host exclusivo, certificado pelo webroot e staging HTTPS somente no loopback. Nenhuma alteração dos outros sites, certificados ou serviços.
- Banco novo recebe RLS antes de exposição pública; não há rollout sobre código antigo nem dados reais. A migration irreversível não será desfeita.

## Operação e limites

`infra/first_install.py` separa criação, antivírus, migrations, serviços e verificação. Deve ser executado por operações no servidor previamente inventariado. Os comandos exigem ambiente e SHA completo. O comando de migrations registra um dump verificável antes de aplicar. Credenciais são geradas no servidor e mantidas fora do checkout; diagnósticos completos de falha ficam em diretório privado.

`infra/first_install_tls.py` altera somente o novo vhost identificado por hash e marcador, faz backup antes de alterações, valida Nginx e faz reload gracioso. A publicação exige os registros de validação dos dois ambientes. O staging usa o mesmo domínio/certificado no proxy TLS, mas porta de loopback e aplicação, arquivos e credenciais separados.

Esta revisão não declara implantação concluída: CI, execução remota, restore, antivírus real, filas e HTTP devem produzir evidência. A criação de operador depende de identidade, campanha e permissões fornecidas pelo responsável. Não serão criadas contas demo em produção. Os 25 módulos continuam parciais conforme `implementation-status.md`; recuperação automática por e-mail, homologação visual autenticada e governança operacional ampliada não estão concluídas.

Referências dos parâmetros operacionais: [ClamAV](https://docs.clamav.net/manual/Usage/Configuration.html) e [Certbot webroot](https://eff-certbot.readthedocs.io/en/stable/using.html#webroot).
